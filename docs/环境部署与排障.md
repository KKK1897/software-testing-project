# 环境部署与排障

本项目仅绑定 `127.0.0.1`，不安装系统服务、不改全局 Java/Node/MySQL 配置。独立目录为 `E:\Project\Test-Project\jshERP-qa`。当前机器 Docker 引擎不可用、WSL 查询受限，因此采用实际验证过的原生进程部署。

## 固定版本与来源

被测源码：[jshERP v3.5](https://github.com/jishenghua/jshERP/tree/7ca0f9d68fef761d98b00854d09e975eba291465)。选定已有正式标签并固定 SHA，而非随 master 漂移；不声称这是最新或无缺陷版本。部署参考[官方部署说明](https://www.gyjerp.com/doc/archive/deploy.html)，接口以该提交控制器、页面实际请求为准，[官方接口资料入口](https://www.gyjerp.com/doc/archive/apidoc.html)仅辅助参考。此固定提交使用 GPL-3.0，许可证保留在上游目录；测试脚本不能被描述为自行开发 ERP。

Python 3.13.2、PowerShell 7、Git 是启动前提。脚本使用 JDK 8u472、Maven 3.6.3、Node 24.18.1、MySQL 8.0.46、Redis 3.2.100、JMeter 5.6.3、Allure 2.32.0；Python 依赖锁在 requirements.lock.txt，前端锁在 locks/frontend-package-lock.json。Redis 是归档 Windows 版本，仅用于本机学习，不能照搬为生产部署建议。

核查[发布说明](https://github.com/jishenghua/jshERP/releases/tag/v3.5)可见 v3.5 已包含登录验证码、库存相关查询和按钮权限变更，因此不能套用更早版本的无验证码登录脚本。另核查[近期 master 提交](https://github.com/jishenghua/jshERP/commits/master/)：2026-09-04 有财务关联单据删除限制，2026-08-18 有部门数据权限异常修正，2026-07-08 有强审核下其他出库缺货校验修正。这些仅作为范围和升级风险线索，本项目没有在 master 运行，不能据此声称本项目缺陷已被上游修复，也不把上游公开问题计为原创发现。

## 首次部署

在项目根目录执行：

```powershell
$env:PYTHONIOENCODING='utf-8'
python scripts/bootstrap.py
```

bootstrap 下载缺少的便携工具、验证上游 SHA 与受跟踪文件状态、创建虚拟环境、安装固定依赖、编译前后端、初始化独立测试库，然后用真实验证码登录验证会话和商品查询。下载需要网络；不保证未来官方历史下载地址永久可用。下载文件哈希用于记录实际输入，不应误称为预先验证的供应链签名。

已有环境只需 `.venv/Scripts/python.exe scripts/start_local.py`。停止用 `.venv/Scripts/python.exe scripts/stop_local.py`；脚本按本项目绝对路径识别进程。重建前先停止，避免 Windows 锁住运行中的 JAR。停止 MySQL 当前采用进程终止，下一次可能触发 InnoDB 恢复；不等同于已实现优雅 SQL shutdown。

|服务|地址/目录|
|---|---|
|前端|http://127.0.0.1:3000|
|业务后端|http://127.0.0.1:9999/jshERP-boot|
|独立补丁后端|19999，仅补丁验证时运行|
|MySQL|13306；runtime/mysql-data；数据库 jsh_erp_qa|
|Redis|16379；独立密码|

配置由 init_local.py 生成，随机密码保存在被忽略的 runtime/local.json。不要手写复制真实凭据进仓库。初始化遇到已有数据目录或未知端口占用会拒绝继续；不要删除现有目录来绕过保护。官方初始化登录仅用于隔离测试库，页面登录信息可从本地测试脚本确认。

## 已实际遇到的问题

|现象|定位与处理|分类|
|---|---|---|
|JDBC 初始化 NullPointerException|原驱动 5.1.30 与本机 MySQL 8 不兼容；独立 pom.qa.xml 使用 5.1.49，保留原 JAR 与日志|环境兼容|
|商品聚合查询 ONLY_FULL_GROUP_BY 错误|Hikari connection-init-sql 仅对测试连接会话移除此模式|环境兼容|
|npm 依赖冲突、旧构建工具 OpenSSL 错误|固定锁、legacy-peer-deps、忽略安装脚本，构建进程设置 openssl-legacy-provider|构建环境|
|PowerShell 5 解析中文脚本失败|bootstrap 明确使用 PowerShell 7（pwsh）|部署脚本|
|重编译 JAR 无法重命名|运行中 Java 锁文件；先按项目范围停止服务|部署脚本|
|身份初始化读取 id 报 KeyError|接口把 null 字段省略，空 data 表示没有记录；按实际响应处理|测试准备脚本|
|连续操作后 loginOut|源码同用户/IP/模块/秒日志限制；普通写请求间隔 2.1 秒，并发重复提交测试明确绕过间隔|产品机制/待澄清|
|业务错误返回 HTTP 406|客户端默认 Accept */* 触发通用资源响应协商问题；客户端明确 Accept application/json；不把任意 406 算作正确拒绝|响应协商/脚本适配|

健康验收不只看 HTTP 200：start_local.py 验证登录 msgTip、Token、用户会话、商品列表和前端入口；UI 测试再验证浏览器登录与真实单据操作。日志在 artifacts，下次启动使用时间戳避免覆盖。

补充实际日志位置：启动标准输出在artifacts；应用日志由上游Logback写入runtime/logs.home_IS_UNDEFINED/jshERP.log。原始和补丁服务共用当前隔离测试库，按顺序测试，应用日志通过9999/19999线程端口区分；并非两套独立数据库。性能时段日志核对见artifacts/performance/backend-log-audit.json。
