# 交付验收核对

用于逐项核对用户原始要求，不能用“代码存在”代替运行证据。动态结果以最终质量报告及其指向的JUnit为准。

|要求|权威证据/检查方法|边界|
|---|---|---|
|独立项目，不动Learning-Agent|当前目录、执行计划、脚本ROOT限制|没有推送/发布|
|检查环境再部署|执行计划环境发现、实际工具版本、启动日志|Docker不可用后已改原生隔离进程|
|固定版本和许可证|上游git SHA、v3.5 LICENSE、环境文档官方链接|JDBC独立兼容构建必须披露|
|真实前后端与依赖|start_local.py登录/会话/商品健康检查、UI真实运行|HTTP200不是唯一依据|
|业务状态/库存时点|业务规则文档、默认与强制审核用例|复杂审批/订单关联不外推|
|三类身份|prepare_identities.py、身份文件、接口和UI权限用例|只读后端存在缺陷，业务操作员页面范围注明|
|采购100/调拨30/销售10|core-scenario.json及test_stock_chain请求证据|普通商品、关闭强制审核与出入库管理|
|50—80设计与25—40API参考规模|测试用例与规则映射：40自动化节点+20补充边界|节点包含35接口+5UI，不当覆盖率；未执行明示|
|正常/异常/边界/查询/并发/回滚|测试脚本、JUnit、boundary-exploration.json|边界探索退出0不是业务全部通过|
|真实UI 3—5流程|test_ui.py、UI专项JUnit、截图和trace|页面库存链路是采购销售，调拨由API验证|
|失败分类与缺陷根因|缺陷与问题记录、请求/日志、隔离patch|缺陷未全部修复，不宣称原创发现|
|修复后回归|patch类JUnit、隔离19999和原基线9999|仅DEF-001最小补丁，未改核心库存|
|重复运行与数据清理|唯一QA标识、manifest、cleanup_data.py实际执行记录|早期未登记与部分创建失败数据不盲删|
|JMeter实际小规模逐级加压|performance/stock-query.jmx、JTL、资源JSON、性能报告|短时结果不推算最大容量|
|固定依赖CI/健康等待/失败产物/退出码|GitHub Actions YAML、bootstrap、Pytest/Allure与停止脚本|远程CI尚未执行；本机对应步骤单独验证|
|完整中文学习文档|README和最终质量报告的文档索引|最终核对命令、路径、数字一致|
|10分钟真实演示|面试与演示草稿、现存环境/报告/缺陷证据|不演示虚构云端CI|

远程CI不执行是没有远程仓库授权下允许的交付边界，不是伪造成功的理由。产品缺陷未修复与测试项目未完成必须分开：可以交付红色测试结果，但不能掩盖缺失的测试运行、清理验证或报告。

最终证据审计见artifacts/delivery-audit.json：40条基线/6条补丁统计与预期缺陷一致，库存70/20，文档链接无缺失；检查1086个脱敏副本文件、25个可读取归档，未匹配本机配置凭据或测试登录口令。该检查针对已知字符串，不等同于对所有潜在敏感信息的证明。历史损坏trace在shareable/export-warnings.json单独记录；最终5条UI trace与报告可用。

最后一次健康检查见final-health-validation.log，真实登录、会话、商品查询和前端入口通过。Allure HTML总览与失败详情均经Chromium打开验证。剩余事项是明确保留的补充测试/规则澄清、未修复产品缺陷以及未授权远程CI，并非用空目录或Mock替代已完成的验收。
