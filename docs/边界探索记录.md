# 补充边界探索记录

来源为本机固定基线实际调用，原始脱敏证据：artifacts/boundary-exploration.json。此脚本不把所有非200业务码视为合格拒绝，退出0只表示取证结束，不等于四项全部验收通过。

|输入|实际响应|实际副作用|判定|
|---|---|---|---|
|仓库名20字符|code200，成功|按精确名称查到1条，随后按ID删除|该长度可保存|
|仓库名21字符|code301，数据写入异常|精确名称0条|未落库；错误是存储异常，不冒充友好的长度校验|
|新商品复用现有条码|code8000005，明确条码重复|新商品名称查询0条|重复条码规则符合预期，未留下新商品|
|采购数量字符串abc|code500，未知异常|目标单号0条、A仓库存0|未产生错误库存，但类型校验提示不明确；不算“规范业务拒绝通过”|

数量abc与21字符仓库名的提示质量可作为后续需求澄清点；本轮不额外凑产品缺陷数量。

## 数值补充观察

numeric-exploration.json记录了另外5组独立商品/仓库。前提是默认不强制审核、允许负库存；每组后续均按manifest清理并查询验证。

|采购输入|保存响应|库存/明细数量实际结果|解释|
|---|---|---|---|
|数量0，单价10|200|0|系统当前接受零数量单据，不自行改成“必须拒绝”的断言|
|数量-1，单价10|200|-1|当前配置接受负采购数量，库存随之减少；是否符合企业规则待确认|
|数量0.1234567，单价10|200|0.123457|实际存储及库存按六位小数舍入，未拒绝七位输入|
|数量1，单价0|200|1|输入被接受；价格明细定向复查另存|
|数量1，单价-1|200|1|输入被接受；不将负价格可保存直接称为产品缺陷|

首次明细查询未传linkType时不返回unitPrice，不能把缺少该字段当作价格已存储正确；源码明确需要linkType=basic或isReadOnly=1。价格值的定向取证使用该实际参数并单独留证，不覆盖首次观察。

numeric-price-verification.json已确认：输入单价0的明细unitPrice/allPrice均为0；输入-1时两者均为-1。两组单据库存均为1，且后续清理均验证通过。

仓库临时记录在脚本内按精确ID回收；商品和A/B仓库manifest留存便于复查，可用受保护清理脚本回收。没有直接修改库存表，也未对非本机环境发送请求。
