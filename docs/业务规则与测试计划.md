# 第一阶段业务规则与测试计划

## 范围与验收

覆盖本机固定v3.5的登录、会话、账号、用户/角色、商品/供应商/仓库、采购入库、调拨、销售出库、库存与单据查询。财务核算、多租户隔离、生产、零售、订单转换、批次序列号不作全面验收。初始化租户仅用于承载测试；采购和销售接口必须提供结算账户，使用初始化账户、实付0作为必要前置，不声称验证财务正确性。

以API查询业务结果为主，UI验证真实交互及页面权限。对失败要求同时确认HTTP、业务码及副作用。现有系统会以HTTP200返回业务错误，未登录返回HTTP500+loginOut，不能以HTTP200或任意失败码判定业务成功/正确拒绝。

完成判定：本地启动可重复、100/30/10链路有单据/库存证据、接口和UI真实执行、缺陷保留失败、性能有JTL、报告与版本一致。当前所有未执行项必须明确标记，不计通过。

## 业务流程

```mermaid
flowchart LR
  L[账号与验证码登录] --> M[建立唯一商品和A/B仓库]
  M --> P[采购入库100：保存状态0]
  P --> S1[A100 B0]
  S1 --> T[调拨A至B：30]
  T --> S2[A70 B30]
  S2 --> O[B销售出库10]
  O --> S3[A70 B20 合计90]
  S3 --> Q[按单号核对单据及按商品仓库查询库存]
```

前提：普通单单位商品，不启用序列号/批号，无初始库存；强制审核/出入库管理均关闭；供应商、客户、账户存在。页面采购销售测试另使用默认仓库，100采购后销售10，预期90；不能把它描述为页面调拨100/30/10。

## 单据状态与转换

|当前状态|操作|条件|结果|默认配置库存|
|---|---|---|---|---|
|尚无单据|保存|明细、账户、仓库等校验通过|0未审核|立即变化|
|0未审核|审核|合法单据ID|1已审核|不重复扣加|
|1已审核|再次审核|不满足0→1条件|8500012拒绝|不变|
|1已审核|反审核|purchaseStatus=0|0未审核|默认配置不变|
|0未审核|删除|无其他阻止条件|逻辑删除|恢复对应库存|
|1已审核|删除|产品仅允许未审核删除|8500011拒绝，定向回归通过|不变|
|任意|顺序重复单号保存|编号已存在|8500022拒绝|不额外变化|

purchaseStatus=2/3相关订单处理以及多级审核不在核心直进直出场景中，只记录源码存在，不宣称已验收。

UserController确实包含`POST /user/registerUser`；本期通过管理员创建测试账号，未运行注册流程，因为它涉及租户初始化，超出第一期多租户边界。审核与反审核功能已实际验证；未发现本项目请求使用显式幂等键，重复提交依赖单号查重，不虚构幂等键测试。

## 风险与优先级

P0：库存链路计算、重复提交/失败回滚、越权写入、数据重置误操作。P1：登录和验证码、缺货策略、单据状态、删除与修改、筛选分页、UI与API结果一致。P2：长字段/小数精度、错误提示、历史兼容、并发查询和小负载表现。

数据隔离采用唯一QA标识与manifest，按业务依赖逆序回收；清理有本机地址、固定端口、数据库名和数据目录保护。执行锁拒绝同时运行测试与清理；不是给产品并发能力添加免责。

## 待澄清/尚未验证的规则

1. 同秒多次合法操作是否应注销用户？是否应返回可识别的限频响应而非提交后下次请求loginOut？
2. 禁用账号和角色是否要求即时使既有Token失效，还是仅禁止新登录？需区分两者。
3. 负库存允许策略在本业务是否应默认关闭？本项目仅按明确配置测，不擅改业务预期。
4. 数量0/负数、超过6位小数、超长字段，前后端是否必须一致拒绝？数据库存储能力不等于业务许可。
5. 角色按钮权限是否为后端操作授权合同？已按合理只读需求报告DEF-002，需上游确认修复范围。
6. 强制审核模式已验证保存不入库、审核入库、反审核撤销；批量审核和缺货校验时点仍待补充。
7. 并发同号已复现双写与库存翻倍，见 DEF-003；数据库索引与事务修复方案尚未评审，未擅改库存代码。
