# AI 测试用例生成与评审工作台（Python）

## 启动

在 `E:\Project\Test-Project\jshERP-qa` 执行：

```powershell
.\.venv\Scripts\python.exe -m beginner.ai_testing.server
```

打开 http://127.0.0.1:8765 。页面由 Python 服务端生成 HTML，使用原生表单提交，无 JavaScript、Node.js 或前端构建依赖。此入口已替换为文档生成与评审，原有固定 ERP 回归执行函数仍保存在 `workbench.py`，不与新生成的用例混淆。

## 用户流程

1. 上传需求、接口说明或已有测试文档：TXT / Markdown / DOCX / 文字型 PDF。
2. 选择本地规则或 AI 模型生成。模型模式将文档文字发送到配置的模型；本地模式不调用模型，仅产生明确标注的规则模板。
3. 查看需求编号、测试点、用例名称、优先级、类型、前置条件、步骤、预期、待确认项、原文及来源。
4. 在网页修改字段并选择待审核、已确认、需修改或已排除，保存审核备注。
5. 导出 XLSX、CSV、Markdown 或 JSON，包含最新的修改与审核状态。

## 模型配置

启动服务的 PowerShell 中设置 `AI_TEST_API_KEY` 或 `DEEPSEEK_API_KEY`。可选 `AI_TEST_API_BASE`（默认 https://api.deepseek.com/v1）和 `AI_TEST_MODEL`（默认 deepseek-chat）。不从另一个项目复制密钥。

缺密钥或调用异常不会静默冒充 AI 成功；页面提示错误，可切回本地模式。模型必须返回约定 JSON，逐项校验结构、优先级、步骤、需求 ID 和需求覆盖，不合法结果不会保存为成功用例。

## 边界

- 限制 3 MB / 32000 字符，超限要求拆分，不静默丢弃尾部内容。
- 需求筛查使用关键词规则，可能漏判或误判，不是完整的语义分类器。需求以正文句子拆分，复杂表格和跨段规则需要人工复核。
- 来源使用提取文本行号与原文，PDF/Word 行号不等于原文页码。
- 未说明的规则要求标记待确认；格式校验不保证模型业务判断正确。
- 本地模板不等于 AI 推理，AI 生成和人工审核都不代表已执行测试；此版本不生成可执行测试脚本。
- 每次上传独立任务目录：`beginner/artifacts/ai/case_jobs/<任务编号>/`，包含原文件、提取文本和 `cases.json`。
- XLSX 单元格以文本保存，CSV 对公式起始符做转义，页面展示做 HTML 转义。

## 验证

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s beginner/ai_testing/tests -p "test_case_generation.py" -v
```

验证本地生成、来源、无关文件与超限拒绝、模型响应结构及漏需求检测、Word/PDF 解析、导出、完整 HTTP 上传—编辑—审核—下载链路。模型响应测试使用替身，不发送真实资料或消耗 API 额度。
