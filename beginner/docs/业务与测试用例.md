# 业务与测试用例

范围：登录/退出/验证码/会话，仓库与商品基础资料，采购、调拨、销售、库存，必要异常与权限。按2026-10-15的后续要求，另扩展本业务链路直接相关的采购付款、销售收款、欠款与账户流水；不测注册、多租户及完整财务，不连接外部支付网关。本学习路线不增加CI、测试平台或状态机框架。性能测试已从JMeter迁移到Python版Locust，旧证据保留。

接口均相对`http://127.0.0.1:9999/jshERP-boot`，来自固定源码与本机真实请求。HTTP200不等于业务成功；错误密码返回HTTP200、业务code200，但`data.msgTip`表示密码错误。会话无效返回HTTP500、文本`loginOut`。

以上为19条基础独立业务用例，无参数组合凑数、无隐式顺序；每条可指定`文件::函数`独立运行。后续新增3条进阶结算用例，见[进阶链路](进阶收付款链路.md)。API断言顺序为准备数据→发送请求→核对响应→查询单据/库存。登录成功由fixture准备，不算额外业务用例。

单据查询：`GET /depotHead/list`核对数量；`GET /depotHead/getDetailByNumber`核对表头；`GET /depotItem/getDetailList`核对条码、数量、仓库及调拨目标；`GET /material/getListWithStock`核对库存。失败或删除后的零单据使用列表查询，避免DEF-001详情异常干扰，但DEF-001独立断言保留。

本机前提是`forceApprovalFlag=0`且`inOutManageFlag=0`，未审核草稿保存直接生效；不擅自切换全局库存规则。强制审核开启时应另测审核后生效，本学习集不覆盖。负库存用例单独临时改`minusStockFlag`并恢复。

普通写请求最小间隔2.1秒源于上游`LogService.insertLog`：同用户/IP/模块同秒操作会清除Redis会话；MySQL无小数时间列还会舍入。本节奏是已知机制前提，保留在Requests写入路径，不向查询或UI扩散，无失败重试。执行锁防止不同任务互相污染，DEF-003进阶用例内部仍真实并发。

UI共3条：登录退出；只读仓库新增按钮不可见；页面采购100、销售10后接口核对单据和默认仓库存90，并在商品库存页面查询90。UI不承担跨仓调拨回归。

已知缺口：并发同号、完整审批、批次序列号、退货、完整财务、外部支付网关、注册、多租户、其他权限接口、长时稳定性等未纳入默认学习集。顺序重复付款单号拒绝不等于并发支付幂等性验收。DEF-003仅保留进阶入口和历史证据，不能用默认集通过率代表全产品可交付。
