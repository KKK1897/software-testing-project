# 快速上手

本文件夹依赖父项目已有环境，Python3.13.2及requirements.txt中的固定依赖已存在，不需全局安装。后端业务源码保持指定提交，已有独立构建把JDBC5.1.30换为5.1.49；MySQL连接会话关闭ONLY_FULL_GROUP_BY。这是本机兼容调整，不是换ERP版本。

所有命令在 `E:\Project\Test-Project\jshERP-qa\beginner` 执行：

```powershell
$env:PYTHONIOENCODING='utf-8'
../.venv/Scripts/python.exe ../scripts/start_local.py
../.venv/Scripts/python.exe -m pytest tests/test_login.py::test_correct_login
../.venv/Scripts/python.exe -m pytest tests/test_inventory.py::test_stock_chain
../.venv/Scripts/python.exe -m pytest tests -m 'not ui' --junitxml=artifacts/my-api.xml --alluredir=artifacts/allure-my-api
../.venv/Scripts/python.exe -m pytest tests/test_ui.py::test_ui_login_logout --headed
../.venv/Scripts/python.exe -m pytest tests/test_ui.py --headed --junitxml=artifacts/my-ui.xml --alluredir=artifacts/allure-my-ui
```

`--headed`复用pytest-playwright开关，显示Chromium；去掉则无头。3条页面流程为登录退出、只读按钮不可见、页面采购100/销售10并查询库存90。跨仓调拨由接口链路验证。API准备基础资料，页面真实填写保存单据，不用请求代替页面业务操作。

查看trace（路径换成本次实际文件）：

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH=(Resolve-Path ../tools/pw-browsers).Path
../.venv/Scripts/python.exe -m playwright show-trace artifacts/ui/实际轮次/test_ui_purchase_and_sale_stock-trace.zip
```

登录错误时先检查9999后端、16379 Redis和验证码是否过期；UI启动失败与页面断言失败分别记录，不能声称功能通过。当前身份读 `../runtime/identities.json`，不同身份使用独立Session/浏览器上下文；不创建或重置已有账号。

## 80分钟实操路线

|时间|亲手操作|观察重点|
|---|---|---|
|0～10分钟|登录ERP，打开仓库、商品、采购、销售、库存页面|认清业务对象，区分上游页面和测试成果|
|10～20分钟|导入Postman，看验证码图片，填写验证码后登录、查询用户和仓库|HTTP状态与JSON业务码；Token在Header传递|
|20～30分钟|运行`test_stock_chain`|准备→请求→响应→单据明细→库存变化|
|30～35分钟|在`artifacts/chain-QA_*.json`找本次tag和单号，在页面筛选|A70、B20、总90及三张单据|
|35～45分钟|阅读`tests/test_inventory.py`和`helpers/inventory_data.py`|`info`与`rows`是JSON字符串，草稿保存即生效的前提|
|45～60分钟|在同文件自己写`test_purchase_25`，运行单条|独立data fixture；采购25；单据唯一、明细25、A25/B0|
|60～70分钟|有头运行UI业务流程，再打开trace|页面定位、条件等待、请求和截图；不要外传原始trace|
|70～75分钟|读DEF-002，比较只读页面按钮与后端新增请求|页面隐藏不等于后端鉴权；不能把漏洞响应200当预期通过|
|75～80分钟|看Allure、中文报告和Locust原始结果|失败与准备错误的区别；5用户不代表高并发能力|

Locust约两分钟，按[性能说明](../performance/README.md)在功能测试结束后单独运行。先读`performance/locustfile.py`中的`query_stock`，这里就是Python性能任务。自己的25件练习不提供现成答案；验收标准是能讲清数据、请求、断言和清理范围。

基础链路掌握后，再读[进阶收付款链路](进阶收付款链路.md)：采购付款1000→调拨→销售150→先收60再收90，检查欠款与账户余额。对应`tests/test_settlement.py`，ERP内部记账不等于真实支付网关支付成功。

## 数据和停止

默认保留唯一QA数据供页面查验；失败现场保留。库存用例成功后可带`--cleanup-passed`，复用原脚本只读SQL检查数据库`jsh_erp_qa`和独立datadir，再按ID、名称、单号、商品归属经接口逆序删除。SQL仅用于防误清环境校验，不替代业务断言。不会清库。

```powershell
../.venv/Scripts/python.exe -m pytest tests/test_inventory.py::test_stock_chain --cleanup-passed
../.venv/Scripts/python.exe ../scripts/cleanup_data.py ../artifacts/data-manifests/QA_实际12位标识.json
../.venv/Scripts/python.exe ../scripts/stop_local.py
```

手工清理命令只用于已核对成功用例；不要清理失败现场。manifest必须来自父目录`artifacts/data-manifests`，不自行拼造ID。权限用例/Postman新建的单仓默认保留，不属于两仓商品清理manifest，按请求证据人工核对后处理。清理与任何测试都不得同时运行。

现有停止脚本只停止命令行归属本项目的服务进程，保留数据；MySQL下次可能崩溃恢复。不要用系统服务管理器停止其他MySQL实例。本轮交付后ERP保持运行，方便继续练习。
